# Runvara production completion: initial audit

Baseline: `f92e27f0e399805d5b50ac5b441ddd8ce22054f0`, existing `main` in
`ajay1980-hue/Packsmart-hub`. Scope: extend the existing `packsmart-ops` service.

Verified before implementation:

- Existing Node service, HTTP-only signed sessions, encrypted credentials,
  workspace state in Supabase, Shopify/eBay read adapters, approval records,
  deterministic daily brief, economics, suppliers and 13 specialist definitions.
- 41 server tests pass; SaaS guards and existing eBay Manager tests pass.
- On 2026-09-20 the existing Render `/api/health` returned HTTP 200, version
  5.0.0, Supabase persistence, authentication and encryption checks true,
  billing charging false. Request ID: `932b41ac-78f8-46d8-8cc1-61232e93aae7`.
- Repository schema enables RLS and denies browser roles direct access.
  Live policies, migrations, environment values and Render logs are not yet
  verified; public health does not establish those facts.

Confirmed code gaps (not assertions about current production data):

1. `store.mjs`: a new authoritative state row is written before its referenced
   workspace parent. Reporting refresh stops at the first failure; optional
   table errors are swallowed. Login discovery depends on the users mirror.
   No cross-process compare-and-save protection exists. File saves can race.
2. `server.mjs`: bootstrap/brief/login/logout and billing writes can save stale
   state outside the workspace mutation lock. Viewer mutations and automation
   settings lack consistent role guards. Initial password replacement is enforced
   by the UI but not by protected business endpoints. Logout does not revoke the
   signed token. JSON bodies need object validation; prototype keys need denial.
3. `integrations.mjs`: order refresh replaces recorded costs and older orders;
   optional eBay failures overwrite previous data with empty results. Shopify
   variant mirror identifiers use mutable/nonunique SKUs rather than source IDs.
   Numeric null inventory is sometimes treated as zero. Retry/auth diagnostics
   and failure timestamps are incomplete.
4. `agents.mjs`: disabled agents still run, one specialist exception can fail the
   whole command, null money is formatted as zero, and recommendations can be
   described as completed commands. Decision context/conflict detection is absent.
5. Autopilot has switches but no scheduler, durable claims, frequency limits or
   run evidence. Exceptions are transient dashboard calculations. Opportunities,
   decision memory, proof records and measured value need persistent workflows.
6. Approval and audit history are truncated. Approval modification/evidence is
   missing. Existing external-write safety contract must remain enforced.
7. `app.js`: economics/preferences use shared browser storage keys across tenants.
   Legacy `cloud.js` stores bearer tokens but is not served or referenced by the
   production static allowlist; leave the unrelated legacy asset inactive.

Implementation order: repair persistence/permissions and integration data loss;
extend the existing state and API with monitored execution, evidence and owner
workflows; expose these in the existing cockpit; test failure paths and isolation;
then publish to existing main/service and verify the live commit and health.

Preservation: no replacement database/authentication/service, no changes to the
Android app, Shopify theme or existing eBay Manager, no new paid service or
external financial/publishing executor. New monitors use deterministic existing
business logic and perform no model calls or spending.

## Live audit after authentication became available

Supabase project `wunihxntqupsmnbipcho` (`packsmart-ops-production`) is healthy.
The live primary workspace has 89 products, 183 variants, 61 orders, 114 audit
events and 2 approvals before this release. All 18 public business tables have
RLS enabled; browser-role table access remains denied. The security advisor
reports only the expected informational "RLS enabled, no policy" notices for
this server-only data model.

Root cause confirmed: the reporting `variants` table imposed
`unique(workspace_id, sku)`, while source data has four duplicate SKU groups.
Only 45 variants had reached reporting. The migration removes that incorrect
uniqueness constraint, preserves all existing IDs and rows, adds lookup indexes,
and adds a service-role-only atomic workspace creation function. Reporting
refresh now matches old rows by product/source identity and keeps duplicate
SKUs separate. Ambiguous SKU cost mappings are flagged for review.

The migration was applied to the existing project. A rollback-only live
transaction verified atomic parent/user/state creation, duplicate-account
rollback, and revision checks. `anon` and `authenticated` cannot call the new
function; `service_role` can. No verification rows were retained.

GitHub repository access and push permission are verified. Render dashboard
authentication was checked once after the resume request and remained at sign-in.
Public health remains accessible. Deployment verification must use the exact
commit returned by the existing production service; dashboard settings/logs must
not be represented as inspected without successful authentication.

## Deployment and authenticated follow-up

Render authentication subsequently succeeded. The existing service was deployed
from main and its build/runtime logs inspected. GitHub SaaS/container and Android
workflows passed. The production owner signed in through the secure browser
handoff; the authenticated cockpit and read-only Shopify/eBay sync were checked.

An initial Autopilot final save failed; interrupted claims were durably marked
blocked on lease expiry. Full historical brief snapshots had inflated primary
state to 6.7 MB. Eleven large briefs were archived before compaction and the one
small brief kept inline. The digest of all twelve original snapshots remained
`759382c7683751b034daeafdc06dcf38`. Primary state fell to approximately 0.66 MB;
the next deployed daily-brief run completed and reporting remained healthy.
The original error lacked HTTP diagnostics, so its exact upstream cause is not
asserted. Safe table/status/code diagnostics now identify any recurrence.

Live reporting contains all 183 variants. The existing 89 products and two
approval records remain intact; new eBay reads append orders while preserving
prior ones. eBay seller authentication and order reads work, but its Inventory
API is unavailable. Coverage is explicitly degraded, not a zero-stock claim.
The existing Render Free instance sleeps when idle, so scheduled checks catch
up when running and cannot guarantee a fixed-time unattended morning run.
