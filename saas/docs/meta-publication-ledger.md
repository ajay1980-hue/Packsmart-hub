# Inactive publication ledger contracts

`saas/server/supabase/prepared/meta-publication-ledger-v1.sql` is prepared SQL for the existing database. Startup and migration discovery do not load it. It reuses the existing strict JSON helpers without changing the synthetic receipt/observation contracts. No route, credential issuer, fetch fallback, provider upload or production-enabled control value is added.

The ledger, read admission, observation and recovery use separate v1 identifiers. All current records permanently say `native_fixture_no_provider_action/v1`; every JavaScript result says publishing disabled, transport not permitted, and no provider action. A database contract or native PostgreSQL pass is not provider acceptance. Future production issuance and hosted installation require separate review and explicit approval.

Proposals live only in protected tables. Creation does not add an executable legacy `connectionWrites` record. The statement barrier serializes generic writers before workspace row locks and forces stale repeatable-read writers to fail. Admission uses a global control lock followed by a nonwaiting workspace share lock, avoiding a lock cycle with older protected RPCs. Generic inserts/updates reject reserved markers before the first event and fence exact protected identities and known container IDs across workspaces. Direct table/helper access is revoked; only the three named service RPCs are granted. Database owners are outside the immutable-record threat model.

Trusted service composition reuses the existing marketing cost, stock and source gates. The database compares the complete current workspace snapshot, independently checks current owner/session, exact approved decision, permission settings, tenant scope and saved Page/Instagram relationship, and records a canonical binding. Snapshot data is compared transiently; credential-bearing workspace payloads are not retained in the ledger. Approval decision changes under an unchanged revision cannot admit another phase. Existing legacy daily reservations and new ledger proposals share the daily allowance.

Container creation and publication each have a permanent single-admission fence. Publication requires the exact retained container result, without a conflicting container disposition. An observed `PUBLISHED` status is unresolved without a unique media result. Read observations bind the first protected publication admission. Lost ACK handling makes one exact lookup, never a second mutation or transport call. Canonical operation fingerprints ignore object property order and exclude transient workspace comparison data. A fresh-owner retained read by immutable identity works after process restart and session rotation; it grants no mutation capability.

Database time is sampled after locks. Backward clock movement fails closed. The global active limit is two and the shared Meta account/Instagram limit is one, including admitted mutation phases. Reads have a shared 60-second account cadence and a lifetime ceiling of five attempts per publication. The five-minute horizon starts at the first read and only closes further admission; it never refills the budget. There is no lease-expiry release.

Each proposal permanently reserves 24 event slots, sufficient for the maximum 20-event lifecycle: reservation, two phase admission/settlement pairs, and five read admission/recovery/settlement triples. Caps are 16 proposals per workspace and 128 globally. Event bytes are limited to 24,576; single-event wire responses allow JSON escaping within 53,248 bytes. The prepared ledger refuses new work at capacity and never prunes identities or resets debt.

Settlement appends exactly one bounded outcome without overwriting workspace state, even after revocation or revision changes. A container collision retains the exact result with `containerConflict: true`, preserves its active hold and permanently denies publication. Recovery is a fresh-owner, expected-head, idempotent audit event: `close_unresolved_retain_hold`. It neither frees concurrency nor grants another GET/POST. Only compatible eventual settlement resolves the hold. Recovery and late settlement serialize without discarding the outcome or rewriting the historical actor.

Run `meta-publication-ledger.test.mjs` for local regressions. Native `meta-publication-ledger-postgres.mjs` is deliberately outside the aggregate glob and requires the explicit disposable-loopback database flags. Native tests create and drop empty child databases and mark owner-seeded historical/capacity fixtures; no test uses provider credentials or hosted data. Keep native counts separate from aggregate and independent-review counts.
