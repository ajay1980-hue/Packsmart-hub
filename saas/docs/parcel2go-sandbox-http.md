# Parcel2Go sandbox HTTP boundary — local proposal

This adds a real server-side HTTPS implementation to the existing guarded runner. It does not add a route, browser button, environment activation, connection registry entry, scheduler or automatic action. The existing credential-entry route remains unable to quote. Default policy and HTTP boundary are OFF. No provider request or real credential was used in development. A controlled local loopback HTTP server and injected request mocks exercise the boundary; they do not establish provider usability, TLS/DNS connectivity, entitlement or actual quote tax semantics.

The code base is the released PR105 tree `03768f9d513a50119b5cd26340bbf6ebcfbc159e`: local reviewed head `bb3951f7132c8783462a4eac016de589712d5adc`, deployed merge `5bbc607428e795f5de70be99a3c68ecf43aa41fb`. The merge-to-head tree equivalence is prior release evidence, not a fresh production read in this task. No live state was inspected or changed.

## Exact HTTP and admission boundary

The new `sandbox-quote/v1` policy requires the existing Packsmart strict owner, current tenant/session/CSRF, exact saved revision, exact encrypted sandbox connection and completed admission receipt, expected client ID, actual approval reference, input hash, explicit currency and VAT assumptions. It additionally requires `network=sandbox-only/v1`, `quotePurpose=synthetic-sandbox/v1` and `scopePolicy=public-api-only/no-openid-fallback/v1`. Unknown modes, normal startup, live bindings, credential-entry operations, measured/customer parcels, missing revocation hook or simultaneous fixture transport are refused. A trusted server caller must verify the session; arbitrary request claims are not authentication.

After private credential shape/binding validation, the runner durably reserves the request and audit using existing CAS, then acknowledges and reads back that exact state. Only then may it transmit. There is one fixed POST to `https://sandbox.parcel2go.com/auth/connect/token`, with form fields `grant_type=client_credentials`, the existing client ID and secret, and `scope=public-api`. A validated memory-only bearer token permits one fixed POST to `https://sandbox.parcel2go.com/api/quotes`. There are no supplied URLs, redirects, retries, refresh fallback, cookies, proxy configuration or pooled socket replay; Node HTTPS creates a fresh request with normal TLS verification. No live host, order, payment, profile, shipment, label or webhook operation exists in this transport. Broad `public-api` permission is not provider-enforced read-only; these restrictions belong to Runvara.

Only one synthetic GBR-to-GBR parcel is allowed. The exact wire whitelist is country/VatStatus for each endpoint and Weight (kg), Length/Width/Height (cm), Value (explicit GBP assumption). No names, streets, postcodes, emails, order IDs or customer data are sent. Requests reject extra fields and precision requiring rounding. Limits are 32 KiB form, 4 KiB quote request, 8 KiB response headers, 16 KiB token body, 256 KiB quote body and 50 quotes. Responses require HTTP 200, JSON, complete bounded bytes and no unsupported compression; duplicate JSON members, ambiguous monetary lexemes, extra scopes, missing/invalid expiry or inconsistent VAT arithmetic refuse. Valid-looking service codes that echo private values also refuse. Provider errors/bodies are never logged or retained.

Each request has at most five seconds end-to-end including body, shortened by the permit, session and (for quote) token remaining lifetime. `expires_in` must be a positive integer at most 86400; expiry is anchored conservatively to token request submission and enforced with wall and monotonic time, including a frozen wall clock. No default lifetime or refresh occurs. The absolute permit is at most five minutes from opening submission, including rollout; backward clock changes latch closed, and process restart trusts UTC and retained durable state. `close()` closes the runner and aborts an active local socket. A remote server may already have processed an aborted request; neither cancellation nor expiry proves no effect. JavaScript strings/network buffers cannot be promised forensically erased; token bytes are cleared where possible and token references released, with no token persistence or DTO exposure.

The runner checks exact state and owner/session again after external waits and before persistence after retention. One-use phase and process latches plus durable CAS/ledger protect concurrent runners/restart. Any incomplete/failed/unknown request is spent; no new UUID, new policy or second exchange is an authorized recovery. Unknown final save may have completed: reconcile the saved revision and receipt read-only, never replay. A successful final receipt stores counts, input/projection digest, source tag and audit, not credentials, tokens or raw provider bodies. Two primary CAS writes are the intended path, with normal archive/retention effects. The exact compact less-than-2-MiB store guard remains unchanged. A refused result can leave a reservation and audit/archive evidence. Absence of a receipt alone is not permission to repeat an uncertain action.

Internally the established store loads the entire saved workspace, which can include existing customer/order records. Nothing from those records is projected to the quote, browser result or provider. Existing business data and encrypted connection are preserved; ordinary retention may archive/prune according to existing policy. Baseline auth/security auditing remains intact. No import, Shopify refresh, credentials replacement or price/stock update is part of this change.

## Known source and unresolved compatibility

The stable official schema captured on 8 November 2026 is retained in the preceding evidence folder: `official-swagger-v1.json`, SHA-256 `8173c59c20bd7d4ae8e4e194b9c19eead62c53088651ac28007fe4e29f5feba2`, from `https://www.parcel2go.com/api/swagger/docs/v1`. Documentation: `https://www.parcel2go.com/api/docs/articles/intro.html`, `endpoints.html`, `payments.html` and `terms.html` under the same articles base. This task reuses the already captured source, not a new provider API call. Stable Swagger lists `openid` alongside `public-api` for quotes, while the client-credentials guide requests only `public-api`. This candidate requests only public-api and refuses any different returned scope. The discrepancy must be resolved or explicitly accepted as a single no-fallback test risk; refusal is not approval to add openid, payment or my-profile.

Country-only quote shape follows the captured schema; actual acceptance, eligibility, account GBP currency and correct CollectionAddress/DeliveryAddress VatStatus are unverified. Nonempty returned quotes do not establish availability, coverage, delivery dates, checkout prices or buy permission. Returned GBP and exact gross/net/VAT arithmetic are checked, but no 20% or other rate is assumed. Empty results may be a valid empty quote response; they do not prove useful service eligibility. Quote expiry is unknown, so price and delivery guarantees remain false. Real sandbox response source and synthetic parcel provenance are separate DTO fields; mocks are never described as original provider responses.
